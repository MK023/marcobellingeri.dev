# Bellingeri, personal site (Astro)

The frontend of [marcobellingeri.dev](https://marcobellingeri.dev): a static Astro site,
bilingual IT/EN, served from Cloudflare Workers static assets. The site audits itself: the
Security section reads the headers out of the HTTP response the browser has just received.

## Setup

```bash
npm install
npm run dev        # local development, http://localhost:4321
npm run build      # production build into ./dist
npm run test:csp   # tests run against dist/, not the source: build first
npx wrangler dev   # serves dist/ WITH the real headers from public/_headers
```

`astro preview` **does not apply `public/_headers`**: the CSP and the security headers only
show up under `wrangler dev` or in production. That is why the tests run against the build and
why verification happens on the served site.

```
  lib/magazine.ts            slug shared by the it/ + en/ pair of an issue
  lib/writing.ts             same, for the writing collection
  i18n/ui.ts                 every string, IT and EN
  data/                      committed data: Radar sources and licences, MITRE

                             outline for the globe
  content/                   magazine, writing, cases, each one it/ + en/
  pages/[lang]/index.astro   assembles the components
  pages/[lang]/              radar, atlas, ai, privacy, magazine/, writing/, rss.xml.ts
  pages/404.astro            served by Cloudflare for any path that does not exist

  index.js                   picks the language on `/` (country + pref-lang cookie),
                             plus /api/contact and /api/ask

test/                        CSP, sections, worker, Radar, magazine, Atlas graph,
                             transparency, mirrors, CSS compatibility

```

## The CSP, briefly

The policy lives in the `<meta>` that Astro generates at build time (`security.csp` in
`astro.config.mjs`), carrying the hash of every script. `public/_headers` keeps **only**
`frame-ancestors`, which a `<meta>` would ignore. Putting a CSP back into the headers would
cancel the hashes and take the site offline, and `npm run test:csp` prevents that. The
anti-FOUC theme script is `is:inline`, so its hash is written by hand in the config. Change the
script and the test fails, telling you which hash to use.

## Deploy

Every push to `main` publishes to production (`.github/workflows/deploy.yml`):
build, tests against `dist/`, `wrangler deploy`, then a check on the served site.
Manual deploys (`npx wrangler deploy`) still work after `wrangler login`.

## Security status

- CSP with hashes, no `unsafe-inline` ([Mozilla Observatory: A+](https://developer.mozilla.org/en-US/observatory/analyze?host=marcobellingeri.dev))
- HSTS with preload, `nosniff`, Referrer-Policy and Permissions-Policy from `_headers`
- TLS 1.2 minimum (set on the Cloudflare zone)
- Self-hosted fonts (Fontsource): no IP handed to Google
- The Cal.eu calendar only loads after an explicit click
